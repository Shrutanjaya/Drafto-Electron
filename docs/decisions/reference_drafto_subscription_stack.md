Drafto (this repo `Drafto-Vite` = the Electron desktop app) is sold as a **monthly subscription**. The billing/website stack lives in OTHER repos/services. Full ready-reckoner: `quindoph-website/ARCHITECTURE.md` (clone of the site repo). Verified 2026-06-05 in that doc.

**Five parts:** (1) **Vercel** — hosts Next.js site, project `quindoph-website`, team `shrutanjayas-projects`, domain `drafto.quindoph.com`, auto-deploys on push to `main`. (2) **Firebase** project `draftoslp`, region `asia-south1` — Auth + Firestore `users/{uid}` + a Cloud Function webhook; CLI auth = `shrutanjaya@gmail.com`. (3) **Razorpay** LIVE mode — recurring subscriptions (new) + 5 legacy one-time payment links; NO official CLI (REST API only). (4) **GitHub** `Shrutanjaya/Drafto-Electron` — hosts installers as release assets. (5) **Hostinger** SMTP (`smtp.hostinger.com:465`, `casefile@quindoph.com`) for welcome/password emails.

**Data flow:** site → Razorpay `/v1/subscriptions` (7-day trial, `start_at=now+7d`, ₹5 verify+refund) → Razorpay webhook → Firebase Cloud Function `razorpayWebhook` → creates Auth user + Firestore doc (status `trialing`) + password-set link + welcome email → user sets password, downloads app. Day 8: `subscription.charged` → status `active`.

**⚠️ The webhook Cloud Function source is NOT in any GitHub repo** — it's a local folder on the user's Windows machine: `C:\Users\shrut\Desktop\DRAFTO\Firebase Files\functions\src\index.ts` (deployed URL `https://razorpaywebhook-ldb4gs4hea-el.a.run.app`, Node 22, Cloud Run). Any account-provisioning/webhook change needs that folder — not present in Drafto-Vite or quindoph-website.

**Gotchas:** (a) download gating is client-side only — `/api/download*` redirect to public GitHub URLs with NO server auth check; licensing must be enforced INSIDE the desktop app, not the site. (b) `firebase deploy --only functions` runs `tsc` predeploy; a TS error aborts deploy but leaves the OLD function live — always `npx tsc --noEmit` first. (c) Vercel env changes need a redeploy to take effect. (d) Desktop app (this repo) uses Firebase only for auth + a Firestore `usage/{uid}` generation counter — it does NOT read plan/subscription status today (relevant if a "gate features by plan" feature comes up).

**OPS ACCESS LEARNED 2026-08-03:** (a) **Firestore + Cloud Logging both readable/writable via the SA key** at `~/.config/drafto/draftoslp-sa.json` — mint a JWT with node `crypto`, exchange at `token_uri`, then hit the REST APIs (scopes `datastore` / `logging.read`). Working scripts pattern: read collection = `GET .../documents/{coll}?pageSize=300`; targeted field write = `PATCH .../documents/users/{id}?updateMask.fieldPaths=x` (updateMask is essential — without it PATCH replaces the whole doc). `firebase functions:log` returns "No log entries found" for the v2/Cloud Run function — use Cloud Logging `entries:list` with `resource.type="cloud_run_revision" AND resource.labels.service_name="razorpaywebhook"` instead. Log retention is generous (back to Apr 2026). The SA needed the **Logs Viewer** role added manually in the console (done 2026-08-03). (b) **Razorpay webhook config is manageable via API**: `GET /v1/webhooks` lists; **`PUT /v1/webhooks/{id}`** updates — `events` must be an **object map** (`{"subscription.paused":1}`), an array 400s with "Invalid event name/names: 1,2,3…", and PATCH 404s. Omitting `secret` preserves it (`secret_exists` stays true). All 10 events now enabled (was 6; `subscription.pending`/`.paused`/`.resumed`/`.updated` were OFF, so the code's dunning email had **never** fired).

**Razorpay CLI (2026-07-21):** CORRECTION — an OFFICIAL Razorpay CLI exists: `razorpay/razorpay-cli` (Go, MIT, ★49, distributed via razorpay.com installer / Homebrew / Scoop — NOT npm, which is why an npm search finds nothing). Installed **v1.0.9 at `~/.local/bin/razorpay`** (on PATH via the existing `~/.local/bin/env` line in .zshrc; installer is `curl -fsSL https://razorpay.com/cli/latest/install.sh | bash`, user-dir install, no sudo). Resource groups: payments, orders, customers, invoices, refunds, subscriptions, payment-links, disputes, settlements, qr-codes, route, smart-collect. Auth: `razorpay configure` (stores `~/.razorpay/config.yaml`) OR env vars `RAZORPAY_KEY_ID`/`RAZORPAY_KEY_SECRET`. **It is full CRUD, NOT read-only** (can create refunds, cancel subscriptions) — so read-only is by convention only (use `list`/`fetch` subcommands; prefer TEST mode). My earlier GET-only wrapper `razorpay-ro.mjs` was DELETED at user request in favor of this. The empty `~/.config/drafto/razorpay.env` (chmod 600) still exists and can hold the key for env-var auth if preferred. I never handle the key value.
