Building the **Central Administrative Tribunal Original Application (OA)** as Drafto's third document type, alongside SLP (SC) and WP (HC). Dev-gated like WP. Large feature, built in verifiable stages (each leaves `npx vite build` green). Uncommitted working tree, 2026-08.

**Reuses from WP** (with OA/MA/PT header swapped): Memo of Parties, Synopsis + List of Dates (incl. LoD→Facts transposition), Filed-by table, Affidavit, Vakalatnama, reliefs/prayers engine, per-section sub-para numbering ([[project_writ_petition_dhc]] internals in `src/lib/wp/`), impugned-order annexure sentences, paperbook/PDF pipeline. Annexures use "A-1…" prefix, colly allowed.

**User-locked design (14 Qs answered + extras):** dev-gated; Bench selectable in Settings dropdown (default Principal Bench New Delhi; list in `src/lib/oa/oa-benches.ts`); Facts reuse LoD→Facts transposition; sub-para styles per-section (Facts `4.1`, Grounds `5.1`, Para-8 Prayer/Para-9 Interim `i/ii/iii`), customizable; all MAs allow extra custom middle paras SLP-style (visible hardcoded paras + editable BadhiyaBoxes); MA order user-decided in Applications tab; all active MAs listed before OA in Index each with own Affidavit (MA header). Multi-applicant: single per-OA toggle between (1) each applicant signs Last Page+Vakalatnama+every MA Affidavit, or (2) Last Page+Vakalatnama+Authority Letter with MA Affidavits signed only by the authorised applicant. Delay auto-calculated from last impugned-order date (user-editable; pure user input if no impugned order). OA settings seed from WP (HC), not SLP.

**Para-9 / Last-Page solution (agreed approach):** don't try to fill Para 9 to page bottom (unreliable). Force a hard PAGE BREAK before Para 10 in both the full OA and the standalone "Last Page", so signed last pages append at a clean page boundary. "Signing Pages" shortcut = Last Page(s) + Affidavit(s) + Vakalatnama(s), one Last Page per applicant marked "Applicant No. N" under DEPONENT.

**Petition for Transfer (PT)** — NEW, my draft (pending user sign-off): triggered when Para-2 Jurisdiction = neither basis. MA-like, titled "Petition for Transfer", placed BEFORE MAs in Index. Section 25 Admin Tribunals Act r/w Rule 6 CAT Rules; prayer = "Grant leave … to file the accompanying OA before the Registrar, <Bench>; and" + fixed catch-all. Own Affidavit.

**OA body = 12 fixed-heading paras** (bold heading + colon): 1 Particulars of Order(s)/reliefs+impugned-order annexure sentences (like WP para 1); 2 Jurisdiction (2 optional declarations + custom, else Section-25→triggers PT); 3 Limitation (no-delay / delay+MA / custom); 4 Facts (intro + sub-paras, LoD-transposed); 5 Grounds; 6-7 fixed text; 8 Prayer (sub-paras, last fixed catch-all); 9 Interim Relief (NIL or prayer sub-paras); 10 "N.A."; 11 postal-order custom (blank ok); 12 "As mentioned in the Index." Then DEPONENT / Filed-by / VERIFICATION / DEPONENT (per-applicant signing). Singular↔plural (Applicant/Applicants) auto everywhere.

**MAs:** header adds "Miscellaneous Application No __ of <yr>" + "in" (5 lines pre-"In the matter of"). Heading "MA under <provision(s), user-defined, may be read-with> praying … <concatenated MA prayers>". Standard first-2 + last-2 paras (para1 refers to OA prayers, para2 = MA prayers, 2nd-last "good faith", last PRAYERS: exactly 2, 2nd fixed catch-all) + custom middle. Auto: delay→S.21(3) r/w Rule 8(4) condonation (prayer variants incl. "delay, if any" without-prejudice); >1 applicant→Rule 4(5)(a) joinder (fixed para3 "common interest"). Optional: Rule 24 exemption certified/clear/legible copies of Annexures<list>; Rule 3(1) proviso r/w Rule 24 English-translation exemption. Prayers end "And for which act of kindness, the humble Applicant shall ever pray." (italic, right). Filed-by after. Each MA + Affidavit (WP-IA-affidavit style, MA header). Authority Letter: OA header + templated text + 1x2 table (Date/Place | Name/Applicant No/Signature).

**QUOTE-INDENT DIAGNOSIS (resolved — kept for reference):** Facts and Grounds sub-lists share identical geometry — level-0 text left=1200 twips (0.83"), hanging=600 (0.42"); deeper levels +480 each. Quote indent = `OA_LIST_GEOM.base(720) + listLevel*step(480) + 360`. In **Facts** the HTML is a real `<ol><li>` so listLevel=1 → quote at 1560 (correct, right of text). In **Grounds** each ground is parsed separately with `defaultNumbering {reference, level:0}` and NO `<ol>` wrapper, so treeToDocx sees listLevel=0 → quote falls back to the standalone 720 (0.5"), i.e. LEFT of the ground text at 1200 → the reported bug. Fix (not yet applied, user asked to hold): make the quote indent account for `defaultNumbering` (treat an injected numbering reference as listLevel 1), or pass an explicit quote-indent override for the Grounds parse.
