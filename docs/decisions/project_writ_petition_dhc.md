**Cause title:** "IN THE HIGH COURT OF DELHI AT NEW DELHI" / italic "Civil Extraordinary Writ Jurisdiction" / "Writ Petition (Civil|Criminal) No. __ of [yr]" / "IN THE MATTER OF:" + …Petitioner / Versus / …Respondents. **Petition-type selector (Civil/Criminal) required** (like SLP). **Article selector** with three options applied consistently everywhere: **226**, **227**, or **226 read with 227**.

**IO vs non-IO writ:** IO (Impugned Order) writs have the IO as **Annexure P-1** (or the first few annexures); **main prayer (a)** always seeks to quash & set aside the IO; usually a **separate "CM for Stay"** application seeks a stay of the IO. Non-IO writs lack this. (The "SP Mangla" sample PDF the user gave is actually an IO writ, no stay CM.)

**WP paper-book skeleton (top→bottom):** Index (this *is* page 1 — no cover/PAPERBOOK page, no AoR) → Notice of Motion → Urgency Application → Memo of Parties → Synopsis & List of Dates → Writ Petition (with affidavit) → Annexures P-1…P-n → CM applications → Vakalatnama → Court Fee → Proof of Service. Front-matter items (Notice/Urgency/Memo) are reorderable. CMs always come after all annexures, **except a CM's own annexures**. No other components ever.

**Party/deponent data model = identical to SLP** (name + address + position; deponent S/o-D/o-W/o + age + address required, deponent defaults to sole/first petitioner). Memo of Parties is just a format change (3-col S.No|Particulars|Position + "Versus" row). "Through its [officer]" only for organisations/companies (same as SLP). Age/email/phone are optional, typed into the address field — no new fields. The generated **Affidavit docx is clean (no signatures/stamps/notary)**; client notarises physically and the notarised PDF is uploaded at PDF-Generation (same upload-replace mechanism SLP uses for signed components).

**Dropped vs SLP:** Office Report on Limitation, Listing Proforma, Cover Page/Paperbook, Filing Memo, Part 1/Part 2/Remarks index columns, A/A1/NS pagination, AoR concept. **Pagination:** single continuous Arabic, top-right bold, starts at 1 on Notice of Motion; Index unnumbered; app stamps page numbers onto uploaded scans at PDF-Generation (as SLP does). **Index:** 3 cols only (Sr.No | Particulars | Pg.); annexure rows use SLP-style colon format "Annexure P-1: A true copy of… dated…".

**"Colly" annexures = WP-only feature** (colly="collectively"; disallowed in SC, allowed in Delhi HC, so absent from DraftoSLP). An annexure can be marked **P-x (Colly)** holding unlimited constituent documents; shows as one entry in Index and Facts, but each constituent gets its **own nested child bookmark** in the output PDF (output is bookmarked per index item, nested children under each Colly).

**Project file extension:** WP projects save as **`.dhcwp`** (SLP stays `.drafto`) so same-party files don't collide on autosave. `projectExtensionFor(data)` in header.tsx picks by courtType; electron main.js has `PROJECT_EXTS`/`isProjectFile`/`stripProjectExt` and recognises both everywhere (save/list/open/double-click); both registered as file associations. Load is content-driven (file's courtType selects interface), so either extension opens fine. NOTE: colly constituent files (annex.collyDocuments[].file) are NOT yet walked by extractFilePaths/restoreFilesFromPaths in header.tsx — fix when colly upload UI lands.

**Generate vs upload:** App generates clean docx for Index, Notice of Motion (with user-selected listing date), Urgency Application, Memo of Parties, Synopsis & LoD, Writ Petition+Affidavit, CM applications, Vakalatnama. Upload-only slots (nothing generated): Court Fee receipt, Proof of Service. Affidavit & Vakalatnama generated clean, then signed/notarised PDFs uploaded at PDF-Generation. Annexures uploaded as in SLP.

**Interim relief:** WP = separate **CM for Stay**, NOT in the petition body. (SLP = interim prayer inside the SLP memo, after the main prayer.)

**CM applications:** three standard CMs — (i) Stay of IO (IO writs only), (ii) permission to file lengthy Synopsis & LoD, (iii) exemption from filing certified/legible/true-typed copies — plus a custom-CM option (like SLP custom IAs). Each CM: header "CM No. __ of [yr] / in / Writ Petition (Civil) No. __ of [yr]", S.151 CPC title, numbered paras, PRAYER block, Filed-by block, and a clean **affidavit** (shorter 3-para version: deponent is Petitioner+Applicant / drafted under instructions, read in vernacular / "accompanying annexures, if any, are true copies"; notarised PDF uploaded later; deponent = sole/first petitioner). A CM's **own annexures use the A-series (Annexure A-1…)** and that CM sits immediately before its own annexures (breaking the "all CMs after all P-annexures" rule).

**MAJOR design decision — the "Facts" section (handle carefully):** The WP petition body has a separate **"Facts"** section (absent in SLP). **Annexure sentences live in the Facts section (prose), NOT in the List of Dates** — the opposite of SLP. Most lawyers draft the LoD, then copy-paste it into Facts tweaking the first words (LoD `01.01.2006  The Petitioner…` → Facts `On 01.01.2006, the Petitioner…`). Plan: the AI assistant ("Mayur") auto-transposes LoD→Facts so the user only fills the **List of Dates** and attaches annexures exactly like in DraftoSLP, with Mayur generating Facts (incl. annexure sentences) entirely — but the user must retain the flexibility to **edit the Facts section** manually. Also allow flexibility to split Synopsis/LoD into separate sections with LoD on a fresh page (user personally doesn't, but support it).

**WP petition body skeleton:** top reliefs block (verbatim lettered, residuary clause omitted) → "To The Hon'ble Chief Justice of the Delhi High Court And His Companion Justices…" salutation → **1.** Intro (prose restatement of reliefs, residuary omitted, + IO annexure sentence appended) → **2. Facts** (sub-paras) → **3. Grounds** (sub-paras) → **4–7.** fixed boilerplate paras (territorial jurisdiction / no efficacious alternate remedy / no other similar petition / leave to add-alter-amend), gender/pronoun-filled → **8. Prayers** (sub-paras). Use SLP-style headings (FACTS, GROUNDS, PRAYER). Top level is Arabic 1.–8. **Reliefs are a single source of truth** (authored as the final Prayers block, last item = residuary "pass any such other order"); the top reliefs block and Para 1 are both auto-derived from it (Para 1 = prose rendering via Mayur).
